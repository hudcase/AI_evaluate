# 软件架构设计

> 对应《技术路线-详细设计 v3.0》第 2、10 章。本文只描述**软件结构**，不重复指标口径与算法论证。
> 全部实现位于 `frontend/`，为纯静态前端；后端接口以本文与《接口约定》为准，尚未实现。

## 一、定位与边界

系统是**端侧 Web 控制台**：部署在校内采集与处理主机上，浏览器访问，操作者只有一类角色——教学过程管理人员。系统不面向学生，不产出个人结论，不做人脸身份识别。

```
                     校内（端侧主机）                                云端（外部模型服务）
┌──────────────────────────────────────────────────────┐   ┌──────────────────────────┐
│  浏览器  ──HTTP──▶  Web 控制台（本仓库 frontend/）      │   │  ASR / OCR              │
│                        │                             │   │  Embedding              │
│                        ▼                             │   │  LLM 判定               │
│                 REST API（待实现，见接口约定）           │──▶│  VLM 判定               │
│                        │                             │   │  ——经 M4 网关统一调用——  │
│        ┌───────────────┼───────────────┐             │   └──────────────────────────┘
│        ▼               ▼               ▼             │
│   ffmpeg/OpenCV    关系库 9 张表     对象存储 4 类目录   │
│   （确定性代码）    （SQLite→PG）     （原始不出校）      │
└──────────────────────────────────────────────────────┘
```

三条不可让渡的约束，直接决定架构形态：

1. **原片不出校**。4K 原片、48kHz 原档只在校内对象存储，任何外发请求都不含原始媒体。
2. **模型不在本地跑**。端侧只保留 ffmpeg / OpenCV 级别的确定性代码，无模型权重、无 GPU 依赖。
3. **前端不判分**。分项分由服务端按 `indicator_config` 的量尺计算，前端只负责展示与录入原始量。

## 二、分层结构

| 层 | 名称 | 内容 | 部署位置 | 当前状态 |
| --- | --- | --- | --- | --- |
| L4 | 展示层 | Web 控制台，8 个页面 | 浏览器 | **已实现** |
| L3 | 应用层 | REST API、鉴权、任务编排、报告渲染 | 端侧主机 | 待实现 |
| L2 | 模型网关 | 批量合并、重试、缓存、版本与成本留痕 | 端侧主机（出网唯一通道） | 待实现 |
| L1 | 治理层 | 转码、抽帧、ROI、重采样、打码、门禁、课件解析 | 端侧主机 | 待实现 |
| L0 | 存储层 | 关系库 9 张表 + 对象存储 4 类目录 | 端侧主机 | 待实现 |

分层的实际意义在于**故障定位**：分数异常时，先看 L0/L1 的门禁结论，再看 L2 的模型版本与置信度，最后才怀疑 L3 的计分逻辑。这条排查顺序写进了《界面规划》里 M3、M4 两页的信息组织。

## 三、模块划分

七个模块与前端页面的对应关系：

| 模块 | 后端职责 | 前端页面 | 路由 | 主要接口 |
| --- | --- | --- | --- | --- |
| — | 全局概览与运行健康 | 总览 | `#/overview` | 多接口聚合 |
| M1 | 课程、场次、目标、同意确认 | 建档 | `#/courses` | `GET/POST /api/courses`、`POST /api/sessions` |
| M2 | 四类媒资上传与登记 | 数据接入 | `#/media` | `POST /api/sessions/{id}/media` |
| M3 | 转码派生、课件解析、脱敏、九项门禁 | 数据治理 | `#/governance` | `POST /preprocess`、`GET /api/tasks/{id}` |
| M4 | 统一出口、批量、重试、缓存、留痕 | 模型网关 | `#/gateway` | 内部 `POST /ai/*` |
| M5 | 21 条指标原始量与分项分 | 指标计算 | `#/indicators` | `POST /observations`、`POST /score` |
| M6 | 模态分、覆盖率、一致性、短板约束 | 合成与一致性 | `#/evaluation` | `GET /api/sessions/{id}/evaluation` |
| M7 | 报告、指标元数据、审计、销毁 | 报告与审计 | `#/report` | `GET /report`、`GET /api/audit` 等 |
| M7 | 指标元数据与量尺配置 | 指标配置 | `#/config` | `GET/PUT /api/indicators` |

模块之间**只通过数据契约耦合**，不共享内存状态。M5 写 `observations`，M6 读 `observations` + `indicator_config` 现算 `evaluations` 快照，M7 只读快照——因此重算历史课例不会污染已发出的报告。

## 四、端云边界

| 方向 | 内容 | 格式 | 限制 |
| --- | --- | --- | --- |
| 端 → 云 | 16kHz 单声道音频 | WAV／FLAC，60s 切片 | 不含 48k 原档 |
| 端 → 云 | 打码后的抽帧、ROI 块 | JPG 长边 1280／PNG 原分辨率 | 人脸已模糊，无身份信息 |
| 端 → 云 | 课件解析文本、讲稿切片 | JSON | 仅图片页与扫描件走 OCR |
| 端 → 云 | 指标口径 + JSON Schema | JSON | 提示词版本随请求记录 |
| 云 → 端 | 结构化判定结果 | JSON | 只含判定值、置信度、理由、时间戳 |
| 云 → 端 | **不返回** | — | 不落库原始媒体、不留存业务结论 |

网关是唯一出网通道，所有调用都必须携带 `model_version` 与 `prompt_version`，否则拒绝执行——这条在《接口约定》里是硬约束，因为无人在回路时，版本快照是唯一能解释"同一节课分数为什么变了"的证据。

## 五、数据模型

九张表，关系如下（`→` 表示外键指向）：

```
courses ──┬─▶ sessions ──┬─▶ media_assets
          │               ├─▶ ai_tasks ──▶ ai_calls
          │               ├─▶ observations ──┐
          │               ├─▶ evaluations ◀──┘（按 config_version 复算）
          │               └─▶ audit
          └─ goals_json（目标数组，含主次权重）

indicator_config（独立，按 code + version 版本化）
```

四类对象存储目录：

| 目录 | 内容 | 保留 |
| --- | --- | --- |
| `raw4k/` | 4K 原片 | 7 天 |
| `proxy/`、`frames/`、`roi/` | 代理流、抽帧、ROI 裁切 | 30 天 |
| `raw_audio/`、`asr_in/` | 48k 双轨、16k 送 ASR | 30 天／24 小时 |
| `slides/`、`reports/` | 课件原档与解析 JSON、报告 | 至结项 |

**派生资产不可删**：代理流、抽帧、ROI 是报告与申诉的唯一依据；存储紧张时只缩短 4K 原片留存期。

## 六、异步任务与状态机

预处理与报告生成都是长任务，一律走 `ai_tasks`：

```
queued ──▶ running ──▶ succeeded
   │           │
   │           ├──▶ failed（error 记原因，可重试）
   └───────────┴──▶ canceled（用户取消或到期回收）
```

前端轮询 `GET /api/tasks/{id}`，间隔 2 秒，连续 3 次无进度变化降为 5 秒。任务进度不追求精确，`progress` 只用于让操作者确认"还在跑"。

## 七、错误处理与降级

| 场景 | 系统行为 | 前端表现 |
| --- | --- | --- |
| 门禁未通过 | 相应分项置空，不输出完整模态分 | 分项显示"未输出"与原因，分数卡片标注"暂定" |
| 模型服务不可用 | 网关重试 3 次（指数退避），仍失败则该项记空值 | M4 页面红色角标，M5 对应行标注"待补" |
| 覆盖率 < 0.6 | 不输出模态分，只列可用分项 | M6 显示"证据不足"，禁用导出 |
| 两模态方向相反 | 标"证据不一致"，不取平均 | M6 一致性卡片转为警示色并列出分歧指标 |
| 无课程目标文本 | 目标匹配域整域记空值，禁止模型推断 | M1 建档时强校验，未填不允许提交 |

前端不使用全局异常弹窗，所有失败就地呈现——操作者需要看到失败发生在哪一条指标上，而不是一个"操作失败"的浮层。

## 八、扩展点（留出的接入位）

架构上预留五类扩展，均不需要改动既有页面结构：

**1. 新增指标**：在 `indicator_config` 增一行（`code / tier / domain / weight / direction / a,b,c,d / unit`），前端 M5、M7 页面按配置渲染，无需改代码。指标表由 `GET /api/indicators` 驱动，不硬编码在前端。

**2. 新增模型能力**：在网关增加一个 `capability` 枚举值与对应适配器；M4 页面按 `capabilities[]` 渲染卡片，新能力自动出现。

**3. 新增报告模板**：报告结构固定为六节，模板层只控制排版；`GET /report?template=` 接受模板名，前端下拉框由 `GET /api/report-templates` 填充。

**4. 更换存储**：`storage.py`（待实现）以 Repository 接口隔离，SQLite 与 PostgreSQL 通过连接串切换，前端不受影响。

**5. 接入真实后端**：改 `frontend/assets/js/config.js` 一处即可——

```js
window.APP_CONFIG = { apiBase: 'http://127.0.0.1:8000', useMock: false };
```

`api.js` 是唯一数据出口，所有页面都经由它取数，因此接后端不需要逐页改造。每个函数都标注了对应的 HTTP 方法与路径，可直接对照《接口约定》实现。

## 九、部署形态

```
端侧主机（1 台，建议 16 核 / 64GB / 4TB SSD / 无 GPU 亦可）
├── 对象存储（本地磁盘或 MinIO）
├── 关系库（原型期 SQLite，上线 PostgreSQL）
├── 处理进程（ffmpeg + OpenCV + Python）
└── Web 服务（静态前端 + REST API）
```

前端为纯静态资源，可直接由任意静态服务器托管；开发与演示用 `serve.py` 启动，见 README。

**为什么前端零依赖**：评审现场常无外网，Node 与 npm 未必可用。因此不用框架、不用构建步骤，`index.html` 直接引用若干 `.js`，双击即开（或一条命令起服务）。代价是没有组件复用的类型检查，收益是任何一台机器都能跑起来。

## 十、技术选型对照

| 位置 | 选型 | 备选 | 理由 |
| --- | --- | --- | --- |
| 前端 | 原生 JS + CSS，无构建 | React + Vite | 离线可用、评审现场零安装；页面数不多，组件抽象收益有限 |
| 图表 | 内联 SVG | ECharts | 只需折线、条形、环形，避免引入 1MB 级依赖 |
| 路由 | hash 路由 | History API | 静态托管无需服务端 rewrite 配置 |
| 状态 | 单一 `App.state` + 视图重绘 | 状态库 | 页面间无复杂共享状态，重绘成本可忽略 |
| 后端 | Python + FastAPI（待实现） | Node／Java | 与 ffmpeg、OpenCV 生态同语言，避免跨进程传大文件 |
| 关系库 | SQLite → PostgreSQL | — | 原型期零运维，上线换连接串 |
