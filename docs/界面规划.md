# 界面规划

> 前端共 9 个页面，对应 7 个功能模块 + 1 个总览 + 1 个指标配置。视觉语言与单页展示稿一致：
> 主色 `#1E4FA8`、端侧灰白底 `#F7F9FC`、云侧浅蓝底 `#E8EFF8`、线框 `#D6DCE5`。

## 一、设计约定

| 项 | 值 |
| --- | --- |
| 版式 | 左侧固定导航 232px ＋ 右侧内容区（最大 1320px，居中） |
| 字体 | Source Han Sans SC / Microsoft YaHei / PingFang SC，正文 14px，表格 13px |
| 字号阶梯 | 28（页面标题）／20（区块标题）／15（卡片标题）／14（正文）／13（表格）／12（注释） |
| 颜色 | 主 `#1E4FA8`；次级文本 `#4A5568`；弱化 `#8B97A8`；通过 `#2F8F5B`；警告 `#B4791F`；阻断 `#B4453C` |
| 圆角 | 卡片 10px，标签 4px，按钮 6px |
| 阴影 | 仅浮层与抽屉使用，卡片靠 1px 描边分层，避免页面发灰 |
| 密度 | 表格行高 40px，卡片内边距 18–20px |

**端侧与云端的视觉区分**沿用 PPT 的做法：端侧区块用灰白底（`#F7F9FC`）＋深蓝左规，云侧区块用浅蓝底（`#E8EFF8`）＋蓝描边。M4 页面因此不需要额外说明就能看出"这里是唯一出网的地方"。

## 二、页面清单

| # | 页面 | 路由 | 核心问题 | 主要元素 |
| --- | --- | --- | --- | --- |
| 1 | 总览 | `#/overview` | 现在有多少课、卡在哪一步、系统健康吗 | 4 个指标卡、课次表、运行健康卡、端云边界条 |
| 2 | M1 建档 | `#/courses` | 这门课教什么、目标是什么、同意了吗 | 课程列表、课程详情、新建课程表单、目标编辑器 |
| 3 | M2 数据接入 | `#/media` | 四类输入齐了吗、规格对不对 | 四类输入卡（含规格校验与 probe）、上传区、缺失提示 |
| 4 | M3 数据治理 | `#/governance` | 处理到哪一步、门禁过没过 | 六阶段进度、九项门禁表、派生资产与容量、上云清单 |
| 5 | M4 模型网关 | `#/gateway` | 调了多少次、花了多少、哪个能力不稳 | 五类能力卡、服务状态条、调用日志表、成本汇总 |
| 6 | M5 指标计算 | `#/indicators` | 21 条指标各是多少、证据在哪 | 音频／视频分组表、分项分条、置信度、证据时间、录入表单 |
| 7 | M6 合成与一致性 | `#/evaluation` | 两份分数是多少、能不能用 | 并列分数卡、覆盖率与缺失、一致性判定、五条规则状态、抬头率时序图 |
| 8 | M7 报告与审计 | `#/report` | 报告长什么样、谁动过数据 | 六节报告预览、导出按钮、审计日志、销毁入口 |
| 9 | 指标配置 | `#/config` | 权重与量尺参数是什么、改过没有 | indicator_config 表、版本切换、量尺说明 |

## 三、导航结构

```
总览
├─ M1 建档
├─ M2 数据接入
├─ M3 数据治理
├─ M4 模型网关
├─ M5 指标计算
├─ M6 合成与一致性
└─ M7 报告与审计
   └─ 指标配置
```

侧栏按"数据流向"排序，与 PPT 第 2 页的模块串链一致：建档 → 接入 → 治理 →（云端推理）→ 计分 → 合成 → 报告。M4 在视觉上缩进一级并用浅蓝底，表明它是出口而非并列模块。

## 四、主流程

**一次完整评估的操作顺序**，也是首次使用者的路径：

1. **建档**：填课程标题、3–8 条目标（标主次）、勾选知情同意 → 生成场次
2. **接入**：四类输入就位。视频 2 路 4K、音频双轨 48kHz、课件 PPTX；规格不符当场拒收
3. **治理**：点"开始预处理"，六个阶段依次跑完；门禁出现 `warn` 时看原因，`reject` 则回到接入重传
4. **推理**：网关自动调用，人不用操作；本页只用于事后核对成本与版本
5. **计分**：21 条指标自动填充；空值项显示原因，可手工补录单条原始量
6. **合成**：看两份分数、覆盖率、一致性；覆盖率 < 0.6 时页面顶部提示"证据不足"，导出按钮禁用
7. **报告**：预览六节内容 → 导出 PDF／DOCX／JSON

## 五、页面要点

### 总览

四张指标卡（在评课次／已出报告／平均覆盖率／本月模型成本）＋课次表（含状态徽标：可用／低可信／证据不足／证据不一致）＋系统健康卡（跨模态一致性率、字错误率、分离错误率、门禁拦截率、低置信比）。

状态徽标是这一页的主线——评审时最常被问"系统怎么判断哪些结果不能用"，答案就是这四个状态。

### M1 建档

左侧课程列表，右侧详情。目标是结构化编辑：每条一行，可选核心／支撑／拓展，核心目标直接决定 A2 的分母，因此表单里写明"核心目标将作为覆盖率分母"。知情同意未勾选时提交按钮禁用并提示原因，不做提交后报错。

### M2 数据接入

四张卡横排：4K 视频（2 路）、48kHz 音频（领夹＋全向）、课件（PPTX／PDF）、课程目标（文本）。每张卡显示：是否就位、规格校验结果、`sha256` 前 8 位、`probe` 关键项、留存期。未就位的卡虚线边框 + "待上传"，不隐藏——缺失必须可见。

### M3 数据治理

上半部分是六阶段流水（校验登记 → 转码派生 → 抽帧 ROI → 课件解析 → 脱敏 → 门禁），当前阶段高亮、已完成打勾。下半部分左侧九项门禁表（`pass/warn/reject` 三色），右侧派生资产与容量。

门禁表是这一页的核心。**门禁的作用是把"测不准"与"教得差"分开**，因此每行都写清"未通过时动作"，而不是只给一个红灯。

### M4 模型网关

顶部服务状态条（各 provider 的 `ok/degraded/down`），五张能力卡（ASR＋说话人分离、OCR、Embedding、LLM 判定、VLM 判定），下方调用日志表（能力、模型版本、提示词版本、tokens、延迟、成本、是否命中缓存）与成本汇总。

整页使用云端配色（浅蓝底），与端侧页面形成对比——这里的数据全部来自外部服务。

### M5 指标计算

两张表：音频 9 项计分 + C1 门禁（单列），视频 10 项计分 + VC3 列示（单列）。列：编码、指标、原始量（含分母与单位）、置信度、证据时间、权重、分项分条。

分项分用 0–100 的水平条，条长即分数，颜色按段位：≥75 主色、60–74 琥珀、<60 砖红。空值项整行灰化并显示原因——不填 0，因为 0 与"没测到"是两件事。

### M6 合成与一致性

顶部左右并列两张分数卡（`Sₐ` 与 `Sᵥ`），各自标注覆盖率、参与项数、权重和。中间**不设总分位**，位置留白并写明"按规则一，不输出总评分"。

下方三块：一致性判定、五条融合规则状态（逐条给"已满足/触发"）、短板约束（VB1 谷值时序图 + 触发说明）。

### M7 报告与审计

左栏报告六节预览（证据覆盖 / 音频分项 / 视频分项 / 并列分数 / 一致性判定 / 合规线索），右栏操作区（导出三格式、销毁入口）与审计日志表。

销毁是危险操作，需二次确认并说明"只删原片与派生资产，保留观测与评价快照"。

### 指标配置

`indicator_config` 表格化：编码、名称、层级、构念域、权重、方向、量尺 `a/b/c/d`、单位、版本。顶部显示当前 `config_version`。

这一页存在的意义是让"权重与阈值是待标定参数"这件事显式化——评审若问"你的阈值哪来的"，界面本身就是答案。

## 六、状态设计

每个页面必须实现五种状态，缺一不可：

| 状态 | 表现 |
| --- | --- |
| 加载中 | 骨架块，不用转圈；表格保留表头 |
| 空 | 说明文字 + 下一步动作按钮（如"尚未上传视频，去接入"） |
| 错误 | 就地红条，含 `error.code` 与重试按钮，不用全局弹窗 |
| 部分可用 | 分项显示"未输出"与原因，页面顶部提示影响范围 |
| 只读 | 已出报告的场次锁定录入，配置页仍可看 |

## 七、响应式

主目标是 1440×900 与 1920×1080 的评审投屏。1280 宽以下侧栏收成图标条，表格允许横向滚动；1024 以下不再优化——这套系统是桌面端操作工具，不做移动端。
