### 2.3 计算（指标分 M5→M6）

**核心结论：真实音频导入后，21 条指标全部是「空值」，没有任何观测值自动产生。**

原因是评价指标分只有一条链路：客户端提交 `raw_value` → 服务端按 `indicator_config` 的梯形隶属函数现算 `s=100μ`。而 `raw_value` 依赖：

- A1–A3（目标告知／覆盖／聚焦）、B4–B6（流畅度／组织／互动）：需 **ASR 转写 + LLM 语义判断**
- B1–B3（语速／语调／口音可懂度）：需 **语音特征提取模型**

当前后端 `provider=stub`（模拟），五类能力 asr／ocr／embed／llm／vlm 全部是「桩」状态，没有真实模型。所以音频原始量无从产生，指标自然为空。

**计算链路本身的正确性已单独验证**：手动提交一条模拟的 A1 原始量（`raw_value=0.9`，模拟真实 ASR 输出），服务端正确算出 **90.0 分**（等级量 `s=100μ` 直接折算）。证明「原始量 → 分数」这一段是通的、正确的，缺的只是**产生原始量的上游模型**。

## 三、检测中发现的缺陷与修复（3 处）

### 缺陷 1：m4a／AAC 音频探针缺失（入库阶段）

- **现象**：`core/probes.py` 的 `AUDIO_EXT` 只有 `.wav`／`.flac`，而真实课程音频是 `.m4a`（AAC）。`tools/import.py` 的 `AUDIO_EXT` 已含 `.m4a`，但后端探针不支持——m4a 会被登记为「未知容器」，采样率／声道／时长全读不到，规格校验形同虚设。
- **修复**：新增 `_probe_mp4_audio()`，复用 MP4 box 遍历，从 `stsd` 的 mp4a 采样条目解出采样率／声道，从 `moov/mvhd` 解时长；支持 moov 在尾部的回读；`check_spec` 音频分支按容器区分「不是有效的 M4A／AAC」与「不是有效的 WAV」。

### 缺陷 2：PDF 页数只读前 20 MB，尾部页字典漏读（入库阶段）

- **现象**：`_probe_pdf` 只 `read(20MB)`，而课程 1 的 PDF（23 MB）的 Page 字典全压在文件后半段（xref 附近，非线性化布局），页数被算成 0，规格校验误判「未解析到页面」，课件导入失败。
- **修复**：按文件大小读全（上限 128 MB）。修复后 81 页正确解析。

### 缺陷 3：与「48 kHz 采集规范」的印证

- 课程 2 的 m4a 实测就是 **48 kHz**，与项目技术路线「48kHz 采集（16k 送 ASR）」的规范一致，印证了规范设定的合理性。但当前 `extract` 阶段的「降采样到 16k」依赖 ffmpeg，本机没有，所以这一步显式 skipped（如实标注，未假装完成）。

## 四、真实生产还缺什么（结论）

全链路检测表明，**入库和「处理」的骨架是通的，但「计算」要落地真实分数，还缺三块**：

1. **ffmpeg**：`extract` 阶段的「m4a → 16k 单声道 WAV（送 ASR）」是硬依赖。装上 ffmpeg 后，降采样这一环就能从 skipped 变 done。
2. **真实 ASR 模型**（`core/providers.py` 的 asr 能力）：把 16k 音频转写成文本，这是 A1/A2/A3/B4/B5/B6 六条指标原始量的来源。当前是 stub。
3. **语音特征模型**：B1（语速）、B2（语调/重音）、B3（口音可懂度）需要韵律／声学特征提取，不依赖转写文本。当前同样没有。

**另两项现实约束**（非代码缺陷，属数据侧）：

- **课程 1 的音频在飞书云文档**，需要先在飞书侧授权、下载到本地（或走飞书 API 拉取），才能走就地登记。仅凭 `音频位置.txt` 里的链接，系统无法直接读云上音频。
- **视频轨缺失**：两门课都没有登记视频，`capture_integrity` 门禁必然 reject。这是业务现状（这两门课本来就是纯音频/课件资源），不影响音频链路的检测结论，但说明「视频三维指标」在这些课例上无法计算。
