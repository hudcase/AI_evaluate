# 后端实现说明

这份文档写给**要改后端的人**：它说明请求在代码里怎么走、九张表为什么这么设计、
《技术路线-详细设计 v3.0》里的规则落在哪个函数、哪些地方是留空的以及怎么补上。

使用方式与文件清单见上一级 `README.md`；接口字段见 `docs/接口约定.md`。

---

## 一、三条实现原则

1. **能算的真算。** 门禁里的采集完整性、时间对齐、元数据完整性、画面可用性全部由真实媒资行算出；
   规格校验靠自己解 MP4／WAV 容器；成本、缓存、p95 延迟由 `ai_calls` 流水现算。
2. **算不了的显式留空。** 没有 ffmpeg 就不假装转码（阶段标 `skipped`）；没有模型证据就把门禁记
   `warn + 未测`；provider 是桩就把每次调用标 `simulated=true`。**任何"看起来有数、其实是编的"
   都是缺陷。**
3. **只有一个算分出口。** 所有分数都必须经过 `core/membership.py`。客户端只能提交 `raw_value`，
   不能提交分数；没有任何旁路。

## 二、分层与边界

```
HTTP 层     app.py         路由匹配、CORS、multipart 流式落盘、静态托管
            http_kit.py    请求解析、JSON/二进制回复、错误序列化
──────────────────────────────────────────────────────────────
业务层      modules/*.py   参数校验、状态机检查、组装返回体
            modules/_common.py   表行 → JSON（字段改名的唯一处）
──────────────────────────────────────────────────────────────
能力层      core/*.py      隶属函数、门禁、探针、provider、流水线、DOCX
──────────────────────────────────────────────────────────────
数据层      db.py         每线程一条连接、事务、查询封装、审计写入
            schema.sql    9 张表
```

规矩：**`core/` 不 import `modules/`，`modules/` 不 import `app`**。算法层不碰 HTTP，
所以 `membership.score()` 可以被流水线、重算接口、演示数据三个地方同时调用而不重复实现。

## 三、一次请求怎么走

以 `PUT /api/sessions/S-20261105-03/score`（补录观测后重算）为例：

1. `Handler._dispatch` 读取方法、路径、查询串；`POST/PUT/PATCH/DELETE` 先读 body
   （multipart 不读，交给路由流式解析，避免大文件进内存）。
2. 路径以 `/api/` 或 `/ai/` 开头 → `_api()`；否则当静态文件处理。
3. `_api()` 先试两个特殊分支（报告导出、媒资上传），再按 `ROUTES` 正则匹配；
   路径匹配但方法不对 → 405 并列出可用方法；都不匹配 → 404。
4. `modules/m5_indicators.rescore()` 校验场次存在、参数合法，逐条取指标配置，
   调 `membership.score()` 算分，写 `observations`，返回重算摘要。
5. `_send_result()` 看返回体形状：普通 dict → JSON；含 `__file__` → 发文件流；
   含 `__html__` → 发 HTML。
6. 任何一层抛 `ApiError` → `http_kit.send_error()` 输出统一结构：

```json
{"error": {"code": "SPEC_MISMATCH", "message": "…", "field": "file", "trace_id": "a1b2c3d4"}}
```

前端只看 `code` 分支，不解析 `message`；`trace_id` 同时打到服务端日志，排障时对得上。

未预料的异常兜底成 `500 INTERNAL` 并打印堆栈——**结构化错误比"连接被重置"好排查**。

## 四、九张表

| 表 | 干什么 | 关键设计 |
| --- | --- | --- |
| `courses` | 课程 | 一门课多次开课，`sessions` 挂课程 |
| `sessions` | 场次 | 存 `goals`（课程目标 JSON 数组）、`scenario`、`students`、`duration_min`；`status` ∈ ok／divergent／insufficient／processing |
| `media_assets` | 媒资 | `type` ∈ video／audio／slides／goals；`sha256` 建唯一索引用于去重；`probe_json` 存探针结果 |
| `ai_tasks` | 预处理任务 | `status` ∈ queued／running／succeeded／failed；`result_json` 存六阶段结果、门禁、派生资产 |
| `ai_calls` | 模型调用流水 | 每次调用一行，含 `input_hash`、`tokens_*`、`latency_ms`、`cost`、`cached`、`simulated` |
| `observations` | 观测值 | `raw_value` **允许 NULL**——空值是结论（该指标不可得），不是缺数据 |
| `indicator_config` | 指标配置 | 按 `config_version` 分行存，改配置是发新版本，不原地改 |
| `evaluations` | 评价快照 | 每次 GET 落一条，只增不改；`composite` 列恒为 NULL，显式表达"不合成" |
| `audit` | 审计 | 谁在什么时候做了什么，`object_id` 指向场次／任务／报告 |

连接层：`PRAGMA journal_mode=WAL`（读写并发）、`foreign_keys=ON`、`busy_timeout=15000`；
每线程一条连接（`threading.local`），写操作用 `BEGIN IMMEDIATE` + 进程内 `RLock`，
避免多线程抢锁抖动。

`observations.raw_value` 允许 NULL 这一条最容易被人"顺手改成 NOT NULL"。改了就等于宣布
"每条指标都必须有值"，B3 口音可懂度（无人工盲听）与 VC3（无当堂测验）立刻无处置放。

## 五、规则落在哪个函数

### 5.1 量尺：原始量 → 分项分

`core/membership.py`。四类取向，全部 clip 到 [0,1]：

| `direction` | 含义 | 公式 |
| --- | --- | --- |
| `inc` | 越大越好 | `μ = clip((x−a)/(b−a))` |
| `reverse` | 越小越好 | `μ = 1 − clip((x−a)/(b−a))` |
| `interval` | 有最优区间 | a–b 升、b–c 满、c–d 降，区间外 0 |
| `level` / `combo` | 原始量本身是 0–1 等级 | `μ = clip(x)` |

分项分 `s = 100μ`，保留一位小数。`band()` 给出可读解释（"落在满分区 [0.85, 0.95]"），
报告里用。

**前端 `mock.js` 的 `scale()` 与它同构**（现在委托给 `UI.scale`）。两边改一处必须同时改另一处，
否则界面预览与接口结果会打架——这是这个项目最容易出现的"看不出来的错"。

### 5.2 门禁：数据够不够格被计分

`core/gates.py`，九项。判定输入分三源，缺哪源就说"未测"：

| 门禁 | 证据来源 | 现状 |
| --- | --- | --- |
| 采集完整性 | 媒资行：通道数、时长偏差 | 真算 |
| 时间对齐 | 媒资时长 vs 场次登记时长 | 真算 |
| 元数据完整性 | 课程目标、课型、班额 | 真算 |
| 画面可用性 | 抽帧数、教师出画时长 | 抽帧数真算，出画时长看模型 |
| 语音可懂度 | `model_metrics.snr_db` | 有则算，无则未测 |
| 转写质量 | `model_metrics.cer` | 同上 |
| 角色分离 | `model_metrics.der` | 同上 |
| 分组稳健性 | `model_metrics.back_row_error` | 同上 |
| 视频检测敏感性 | `model_metrics.back_row_detect` | 同上 |

阈值写在文件头，并明确标注是**示意值**：只认法规标准、实证分布分位数、效标切点三类来源，
接真实课例后必须按本校分布重标定。

`blocked_codes(gates)` 决定哪些指标记空值：转写质量 reject → A1–A3、B1–B2、B4–B6 不出分；
检测敏感性 reject → VB1–VB3 不出分；缺目标 → A1–A3 不出分。被阻断的项在 M5 里是
`score=None` + `empty_reason`，**不是 0**。

### 5.3 融合：两份分数并列

`modules/m6_fusion.py`。三个常量：`DIVERGENT_DELTA=15.0`、`MIN_COVERAGE=0.60`、
`ALERT_THRESHOLD=0.5`。

- **覆盖率**＝该模态实际有分项分的指标权重和。覆盖率 0.90 时模态分的理论上限就是 90——
  `_agg()` 只累加 `scored and score is not None` 的项，不重分权。
- **判定顺序**：任一模态覆盖率 < 0.60 → `insufficient`（此时不出模态分）；
  否则 `|Sₐ − Sᵥ| ≥ 15` → `divergent`；否则 `aligned`。
- **`composite` 恒为 None**，`evaluations` 里也保留这一列并且写 NULL。去掉这一列会被读成
  "只是还没算总分"。
- **快照只增不改**：每次 GET 重算并插一条，用于复算比对与申诉时回答"当时算的是什么"。

## 六、异步任务

`core/tasks.py` + `core/pipeline.py`。POST preprocess 立刻返回 202 + `task_id`，
后台 daemon 线程跑六阶段：

```
probe → transcode → extract → parse_slides → mask → gate
```

每阶段返回 `(status, detail)`，`status` 只有四种：`done`（真做了）/ `skipped`（环境做不了，
写明缺什么）/ `degraded`（做了一半，写明到哪一步）/ `failed`（错误进 `task.error`）。
单阶段抛异常只记该阶段 failed，不整条中断。

- **互斥**：同场次已有 running 任务时再提交 → `409 TASK_CONFLICT`。
- **演示任务的例外**：`seed` 造的 running 任务在 `result_json` 里打 `{"seeded":true}`，
  `active_task()` 用 `NOT LIKE` 排除，否则演示数据会把真实预处理永久锁死。
- **进度**：`progress` 与 `stage` 随阶段推进更新，前端按 `stages[]` 渲染阶段条，
  `skip` 显示"—"虚线而不是绿色对勾。

## 七、模型网关

`core/providers.py`。三种 provider，统一入口 `call(capability, payload, ...)`：

1. 校验 `capability`、`model_version`、`prompt_version`——后两者缺一即 `400`，不写库；
2. 算 `input_hash = sha256(capability + payload + 两个版本号)`；
3. 查 `ai_calls` 里 7 天内同 hash 的记录，命中则直接返回缓存的 `response_json`
   （`cached=1`、`cost=0`，不重复计费）；
4. 未命中 → 调 provider，指数退避重试 3 次；
5. 无论成败都写一条 `ai_calls`：延迟、token、按 `PRICING` 算的成本、`simulated` 标记。

| provider | 行为 |
| --- | --- |
| `stub` | 不联网。用 `input_hash` 作随机种子派生结果，**同一输入永远同一输出**，回归可比 |
| `openai` | 走 OpenAI 兼容端点。`llm`（chat/completions，`response_format=json_object`）与 `embed` 已实现 |
| `none` | 全部抛 `503 PROVIDER_UNAVAILABLE` |

价目表 `PRICING` 在 `config.py`：ASR 按分钟、OCR 按页、embed 按千 token、LLM 按输入输出
token 分开、VLM 按张。真实单价按合同改这里，记账逻辑不用动。

`estimate_cost()` 单独暴露，是为了让前端在上传前就能给出"这场课大概花多少"的预估。

## 八、探针：为什么自己解容器

`core/probes.py`。评审机上装不了 ffprobe，而规格校验（4K／48kHz／时长）是**拦截点**——
数据规格不对时后面对齐和抽帧都没意义，应该在采集端重录，而不是让数据混进来。所以只能自己解：

| 格式 | 解析对象 | 得到 |
| --- | --- | --- |
| MP4 | `ftyp`/`mvhd`/`tkhd`/`stsz` | 时长、分辨率、帧率、轨道数、码率 |
| WAV | RIFF `fmt`/`data` | 采样率、位深、声道、时长；尾部 8 MB 抽样算峰值与削波占比 |
| PPTX | zip 内 `slideN.xml` | 页数、纯图页数（无 `<a:t>` 的页） |
| PDF | `/Type /Page` 计数 | 页数 |

三条实现上的讲究：

1. **扩展名要靠原文件名判**。上传时落盘的是临时文件（`.part`），只按路径取扩展名会掉进
   "未知容器"，于是所有真实上传的规格校验永远通过——等于没有校验。所以 `probe()` 收了
   `filename` 参数。
2. **moov 在文件尾部也要能读**。相机和手机默认把 `moov` 写在末尾（非 faststart），
   只读文件头会拿不到时长与分辨率。探针读头部 2 MB 找不到时，回读尾部 8 MB 再找一次。
3. **不是容器就拒收**。既没有 `ftyp` 也没有 `mvhd` 的文件（改扩展名的、损坏的、全零字节）
   → 422，而不是"字段读不出所以放行"。这条和"读不出就记未知"不冲突：未知是**容器合法但
   字段没读到**，无效是**压根不是这种容器**。

只读文件头与文件尾，大文件不会读进内存。**测不了的**：画面清晰度、遮挡、噪声类型、
转写正确率、后排检测率——这些是内容层面的，只能模型给。它们不进探针，进
`task.result_json.model_metrics`。

## 九、报告与 DOCX

`modules/m7_report.py` + `core/docx.py`。报告六节，全部字段来自 `build_report()`，
不引入新口径：结论区先写覆盖率与缺失项，再写两份分数，最后写门禁与短板。

- **证据不足不出正式报告**（`409`）。一份没有分数的报告流出后一定会被读成"评分很低"。
- **DOCX 自己生成**（zip + OOXML），因为端侧不能 `pip install python-docx`。
  样式用宋体小四 / 西文 Times New Roman / 1.5 倍行距。表格必须写 `<w:tblGrid>`，
  否则严格解析器（含 python-docx）会报 `required <w:tblGrid> child element not present`。
  不做页眉页脚、编号、图片、目录域——需要排版就"导出去 WPS 再改"。
- **PDF 留 501**：要嵌中文字体子集，端侧不引字体文件。判定顺序是先判 pdf（能力问题，
  任何数据都做不了）再判证据不足（数据问题），所以 501 不会被子虚乌有的 409 盖住。
- **HTML 版**给浏览器直接打印用，是 PDF 的替代路径。

## 十、错误码

| code | HTTP | 什么时候 |
| --- | --- | --- |
| `VALIDATION_FAILED` | 400 | 字段缺失／类型不对／量纲不符 |
| `CONSENT_REQUIRED` | 400 | 建场次未确认知情同意（必须 `is true`，不看真假值） |
| `PII_DETECTED` | 400 | 文本含手机号、身份证、邮箱等直接标识 |
| `NOT_FOUND` | 404 | 课程／场次／任务／媒资不存在 |
| `METHOD_NOT_ALLOWED` | 405 | 路径对，方法不对（响应里列出可用方法） |
| `GATE_NOT_PASSED` | 409 | 门禁 reject 却想计分 |
| `MISSING_GOALS` | 409 | 缺课程目标，目标匹配域不可算 |
| `TASK_CONFLICT` | 409 | 同场次已有运行中的任务 |
| `STATE_CONFLICT` | 409 | 当前状态不允许该操作（如证据不足时导出） |
| `SPEC_MISMATCH` | 422 | 媒资规格不符（分辨率／采样率／时长） |
| `QUOTA_EXCEEDED` | 429 | 模型调用配额耗尽 |
| `NOT_IMPLEMENTED` | 501 | 本版本留空，接口已就位 |
| `PROVIDER_UNAVAILABLE` | 503 | provider=none 或上游报错 |

## 十一、留空清单与接法

留空的地方**一律返回明确的 501 或显式的 skipped 状态**，`message` / `detail` 里写明缺什么。

| 位置 | 现状 | 怎么补 |
| --- | --- | --- |
| `POST .../media` `action=presign` | 501：需对象存储签名 | `modules/m2_media.py::register()` 里接 MinIO／OSS／S3 的签名；或继续用 multipart，或用带 `path` 的就地登记 |
| `GET .../report?format=pdf` | 501：需嵌中文字体 | 导出 DOCX 后 WPS 另存，或浏览器打印 HTML 版 |
| `provider=openai` 的 asr／ocr／vlm | 501：各家协议不同 | 在 `OpenAIProvider` 补一个方法返回 `(data, usage, latency_ms, cost)`，其余逻辑复用 |
| 流水线 `mask` 阶段 | 恒 `skipped`：需人脸／人体检测 | `core/pipeline.py::stage_mask()` 接检测模型后逐帧打码，产物放 `derived/frames_masked/` |
| 流水线 `parse_slides` 的 PDF 课件 | `skipped`：需版面分析 | 走 OCR provider 取正文；PPTX 已可直接解 |
| VB1 逐分钟时序 | 需 VLM 分区检测 | `observations.series_json` 写入点序列后，`/vb1-series` 自动有图 |

补的时候守两条：**不要伪造成功**（宁可 501）；**不要绕开 `membership`/`gates`**
（分项分与门禁结论只能由这两个模块产出）。

## 十二、自测

`backend/tests/smoke.py`，63 项断言，打真实 HTTP。分两类：

- **契约断言**：状态码、错误码、字段名，防"改了字段名前端静默变空"；
- **口径断言**：不合成总分、缺测不补零、覆盖率＝权重和、门禁阻止计分、分歧即证据不足、
  版本号不能重发——防"顺手把规则改掉"。

断言里最有价值的几条：

```
composite 恒为 null
音频 9 项权重和 = 1.0000 ／ 视频 10 项权重和 = 1.0000
证据不足场次：coverage < 0.6 且两份分数均为 null
同输入同版本二次调用命中缓存且 cost=0
直传后 probe 能读到真实容器与采样率（防"临时文件后缀导致探针失效"复发）
同场次同内容重复上传 → duplicate=true（防重复入库）
8 kHz 音频、非 MP4 字节 → 422（防规格校验形同虚设）
缺 prompt_version → 400 且不写 ai_calls
证据不足场次导出 → 409；format=pdf → 501（501 优先于 409）
```

改后端后先跑一遍；红线断言失败说明改坏了评价规则，不是"测试过时了"。

## 十三、最常改的五处

| 想改什么 | 改哪里 |
| --- | --- |
| 指标权重、量尺参数 | `seed/indicators.json`（或 `PUT /api/indicators` 发新版本），别改代码 |
| 门禁阈值 | `core/gates.py` 文件头常量区，改完在注释里写清标定来源 |
| 分歧阈值、覆盖率下限 | `modules/m6_fusion.py` 顶部三个常量 |
| 价目与模型名 | `config.py` 的 `PRICING` 与 `MODEL_NAMES`（也可用环境变量） |
| 接口字段改名 | `modules/_common.py`——表行转 JSON 的唯一处，改这里前后端同时生效 |

改完这三样必须同步文档：`docs/接口约定.md`（字段）、`docs/架构设计.md`（结构）、
`README.md` 第九节（口径）。文档与代码不一致时，**以文档里的口径为准改代码**，
因为那些规则是评审依据，不是实现细节。
