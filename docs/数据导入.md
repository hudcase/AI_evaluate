# 数据导入

这份文档回答一件事：**手上已有的课例数据，怎么进到系统里**。

系统里"原始数据"其实有三层，导入方式和校验都不同：

| 层 | 是什么 | 进哪张表 | 怎么进 |
| --- | --- | --- | --- |
| 建档信息 | 课程标题、课程目标、场次日期／课型／班额 | `courses`、`sessions` | 界面填 / `POST /api/courses`、`/api/sessions` |
| 原始媒资 | 4K 视频、48 kHz 音频档、课件、目标文件 | `media_assets`（文件本身落 `data/media/`） | 界面拖拽 / multipart 直传 / 就地登记 |
| 指标原始量 | 21 条指标的 `raw_value` 与证据 | `observations` | 界面补录 / `POST /api/sessions/{id}/observations` / CSV |

**分数不需要导入**，也不允许导入：分项分只能由服务端按量尺算出来（`core/membership.py`）。

---

## 一、先明确一件事：不要直接往 SQLite 里 INSERT

库文件就在 `data/eval.db`，用任何 SQLite 工具都能写。但绕过去会丢掉四件事：

1. **规格校验**：4K／≥16 kHz／时长一致性，不对的数据进来后，对齐和抽帧全部失效；
2. **sha256 与探针**：文件的真实字节数、时长、分辨率、页数进不了 `probe_json`，
   门禁"采集完整性／画面可用性"只能靠猜；
3. **审计**：`audit` 表记不下"谁在什么时候导入了什么"，报告的可追溯性断掉；
4. **状态机与门禁**：`sessions.status`、`ai_tasks` 的一致性靠接口维护，手写极易留下不一致。

所以下面三条通道都走接口。**宁可慢一点，也不要造出一批"看起来有数据、其实无法复核"的记录。**

---

## 二、三条通道

| 通道 | 适合 | 特点 |
| --- | --- | --- |
| 界面 | 一两节课，边看边填 | 有校验提示，失败原因直接显示 |
| 单个 curl / 前端 API | 接别的系统、写集成脚本 | 契约见 `docs/接口约定.md` |
| `backend/tools/import.py` | 一批课、几十个文件 | 目录扫描或 JSON 清单，幂等可重跑，失败逐条列出 |

脚本本身零依赖（只用标准库），且**只发 HTTP 请求**——校验逻辑与界面完全同一条路径。

## 三、准备数据：目录约定

脚本最常用的模式是"照目录放好"，命名即语义：

```
原始数据/
├── 新任经理管理能力培训/          ← 一层目录 = 一门课程，目录名即课程标题
│   ├── goals.txt                  ← 课程目标（必需，见下）
│   ├── 2026-11-05-0900/           ← 二层目录 = 一个场次，日期时间从目录名解析
│   │   ├── cam1.mp4               ← 机位 1
│   │   ├── cam2.mp4               ← 机位 2
│   │   ├── lavalier.wav           ← 领夹麦
│   │   ├── ambient_env.wav        ← 环境声（名字含 ambient / env / 环境 / room）
│   │   └── 课程课件.pptx           ← 课件（pptx 或 pdf）
│   └── 2026-11-12-1400/
│       ├── cam1.mp4
│       └── lavalier.wav
└── 内训师授课技巧/
    ├── goals.json
    └── 2026-11-13-0930/
        └── cam1.mp4
```

规则：

- **视频位**：文件名含 `cam1`～`cam4` 就用对应位；不含则按顺序占位（会打印出来，不静默）。
- **音频位**：含 `ambient`／`env`／`环境`／`room` → 环境声，其余 → 领夹。一个场次最多各一条。
- **课件**：`.pptx`／`.pdf` 进 `deck` 位；`.pptx` 能直接解析正文，`.pdf` 只记页数（正文要 OCR，留接口）。
- **不认识的扩展名**会被列出来并跳过，不会被猜成某类。
- **目录名里的日期**：`2026-11-05`、`20261105`、`2026.11.05`、`2026-11-05-0900` 都能识别；
  识别不到就用当天、09:00，并明确提示。

### 课程目标：必须自己写

`goals.txt`：一行一条，**第一条自动作为核心目标**（以 `#` 开头的行是注释，会被忽略）。

```
能说清管理者的三项核心职责
能用目标-过程-复盘三段法做周会
能识别四种常见团队冲突并给出应对
```

`goals.json`：需要精细控制层级时用它，`tier` ∈ `core`／`support`／`extend`。

```json
[{"text": "学员能独立完成一次 20 分钟微课讲授", "tier": "core"},
 {"text": "学员能设计一份课程目标-活动-检验对齐表", "tier": "support"}]
```

**至少要有 1 条 `core`**，否则接口直接 400：A2「加权目标覆盖」的分母就是核心目标权重和，
没有核心目标这个指标在数学上不成立。工具**不会**替你编目标。

## 四、跑脚本

```bash
# 先起后端（另开一个窗口）
python backend/app.py --seed-demo

# 演练：只看计划，不发请求
python backend/tools/import.py scan ./原始数据 --consent --dry-run

# 正式导入
python backend/tools/import.py scan ./原始数据 --consent --duration 90
```

### 参数

| 参数 | 作用 |
| --- | --- |
| `--base URL` | 后端地址，默认 `http://127.0.0.1:8000` |
| `--dry-run` | 只打印计划（文件→类型→slot→大小），不写库 |
| `--consent` | 声明已取得知情同意。**不写就不建场次**，这是流程约束 |
| `--in-place` | 只登记盘上文件，不复制字节（见第六节） |
| `--replace` | 同一 slot 已有资产时替换（默认报冲突） |
| `--preprocess` | 导入完立刻触发预处理（六阶段） |
| `--duration N` | 场次时长（分钟），默认 90。**务必与实际课时一致**，见第七节 |
| `--new` | 不复用同名课程／同日期场次，强制新建 |

### 幂等：可以放心重跑

- 同名课程 → 复用（不覆盖已有目标，目标是口径，不做静默改写）；
- 同「日期＋开始时间＋标题」的场次 → 复用；
- 同一场次内同 sha256 的文件 → 判重跳过，不重复入库。

所以"第三门课失败、改完继续跑"是安全的，不会多出一整套重复课次。

## 五、清单模式（字段最全）

目录约定表达不了的（课型、教师、教室、班额、逐场次观测值），用 JSON 清单。

```bash
python backend/tools/import.py manifest 清单.json --in-place
```

```json
{
  "courses": [{
    "title": "内训师授课技巧",
    "expected_students": 24,
    "goals": [{"text": "学员能独立完成一次 20 分钟微课讲授", "tier": "core"}],
    "sessions": [{
      "title": "加练场：微课试讲",
      "date": "2026-11-20", "start": "10:00", "duration_min": 90,
      "scenario": "seminar", "teacher": "张敏", "room": "B203",
      "consent_confirmed": true,
      "media": [
        {"file": "1105/cam1.mp4", "type": "video", "slot": "cam1"},
        {"file": "1105/课件.pptx", "type": "slides", "slot": "deck"}
      ],
      "observations": [
        {"code": "A2", "raw_value": 0.82, "source_track": ["audio", "slides"], "confidence": 0.9}
      ]
    }]
  }]
}
```

- `file` 路径**相对清单文件所在目录**；
- `scenario` ∈ `theory`（理论）／`seminar`（研讨）／`practical`（实操）；
- `consent_confirmed` 必须为 `true`（或用命令行 `--consent` 统一声明）。

## 六、大文件：就地登记，不搬字节

4K 一节课几十 GB，multipart 直传会把它**复制**进 `data/media/`。如果文件已经在同一台机器的盘上
（采集机目录、外挂盘、网络盘），用 `--in-place`：

```bash
python backend/tools/import.py scan ./原始数据 --consent --in-place
```

它走 `POST /api/sessions/{id}/media` 的 JSON 分支（带 `path`），行为差别只有一处：

| | 直传（默认） | 就地登记（`--in-place`） |
| --- | --- | --- |
| 文件位置 | 复制到 `data/media/<场次>/<slot>_<原名>` | 保留原路径 |
| sha256 | 算 | 算 |
| 探针 | 跑 | 跑 |
| 规格校验 | 校验 | 校验 |
| 审计 | `media.upload` | `media.register_local`（记 `in_place: true`） |

> **注意**：销毁媒资（`DELETE .../media?scope=raw&confirm=true`）会按登记的路径**删源文件**。
> 登记前确认这个路径是系统可以删的，别把采集机上的唯一副本登记进来又执行销毁。

## 七、导入后的正确顺序

导入只是把数据放进来，结论要靠后面的步骤：

```
建档 + 媒资  →  预处理（六阶段）  →  门禁判定  →  补录/接入观测值  →  合成  →  报告
```

1. **预处理**：`--preprocess`，或界面点"开始预处理"，或 `POST /api/sessions/{id}/preprocess`。
   没有 ffmpeg 时转码与抽帧会显式 `skipped`，门禁"画面可用性"随之变 warn——系统不假装做过。
2. **看门禁**：九项里"采集完整性／时间对齐／元数据完整性"三项完全由你导入的数据决定。
3. **补观测值**：`raw_value` 与证据（`source_track`、`evidence_t`、`confidence`）。
4. **合成**：`GET /api/sessions/{id}/evaluation`，覆盖率不足 60% 时不出模态分。
5. **报告**：`GET .../report?format=docx`。

### 时长与班额会直接影响门禁

- `--duration` 与实际课时不一致时，"时间对齐"门禁会按偏差判定：
  偏差 > 30 秒 → `reject`，2–30 秒 → `warn`。90 分钟的课导成 45，这项必红。
- 班额（`expected_students` / `students`）为 0 时，"元数据完整性"只能给 `warn`。
  清单模式写 `expected_students`，目录模式目前取课程值。

## 八、导指标原始量（CSV）

```bash
python backend/tools/import.py obs 观测.csv --session S-20261105-03
```

```csv
session_id,code,raw_value,denominator,confidence,evidence_t,source_track,evidence_note,empty_reason
S-20261105-03,A2,0.82,12,0.90,00:12:30,audio+slides,12 条目标命中 4 条,
S-20261105-03,VA1,15,,0.75,00:31:00,video,手势 15 次/分,
S-20261105-03,B3,,,,,audio,,无人工盲听，按空值处理
```

- **`raw_value` 留空 = 空值**，是合法输入，会进 `missing` 并压低覆盖率；**不是 0**。
  建议同时写 `empty_reason`。
- `source_track` 用 `+` 分隔，取值 `audio`／`video`／`slides`／`goals`。
  `VA5`、`VC1`、`VB3` 必须 ≥2 路证据，否则 400。
- `--session` 优先于 CSV 里的 `session_id`（那一列常是从别的库拷来的旧编号）。
- 写入即算分：返回里带 `score`。分项分不能自己填。

## 九、常见报错对照

| 报错 | 原因 | 怎么办 |
| --- | --- | --- |
| `CONSENT_REQUIRED` | 场次未确认知情同意 | 确认后加 `--consent`，或清单里写 `"consent_confirmed": true` |
| `SPEC_MISMATCH` | 分辨率 < 1280×720、采样率 < 16 kHz、削波 > 2%、课件解析不出页、不是有效 MP4/WAV | 看 `detail.problems` 逐条；该重录就重录，不要"先导进去再说" |
| `STATE_CONFLICT` | 同一 slot 已有资产 | 加 `--replace`（旧的那条软删，不会物理删除） |
| `TASK_CONFLICT` | 该场次已有运行中的预处理任务 | 等它跑完，或查 `/api/sessions/{id}/tasks` |
| `NOT_FOUND` | 课程／场次编号不存在 | 场次编号每次重建库都会变，用 `/api/overview` 查当前编号 |
| `PII_DETECTED` | `evidence_note` 里有手机号／身份证／邮箱 | 去掉直接标识，换"参训教师 A"这类写法 |
| `GATE_NOT_PASSED` | 门禁 reject 的指标不允许补录 | 先解决门禁问题（重采／补齐通道），不要绕 |
| `VALIDATION_FAILED` | 字段类型／取值不对 | 报错里有 `field`，按名改 |
| 连不上后端 | 服务没起或端口不对 | `python backend/app.py --seed-demo`，`--base` 指对端口 |

## 十、导入完成后自查

```bash
curl -s http://127.0.0.1:8000/api/sessions/<SID>/media   # 5 个资产的 probe 是否都有值
curl -s http://127.0.0.1:8000/api/sessions/<SID>/qc      # 九项门禁，前 5 项不应是"未测"
curl -s http://127.0.0.1:8000/api/sessions/<SID>/evaluation   # 覆盖率与两份分数
```

界面上对着看：总览里应多出这几个场次；M2 页每个资产的时长／分辨率／页数都不是空的；
M3 页六个阶段的状态要能讲清"哪个做了、哪个本机做不了"。
